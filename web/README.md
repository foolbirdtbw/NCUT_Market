# NCUT Market — 前端

北方工业大学校园二手交易平台的前端。无构建步骤：没有 npm、没有打包器、没有 TypeScript。
浏览器直接加载这里的文件，由 `NCUT_Market.Api` 同源托管。

## 文件

| 路径 | 说明 |
|---|---|
| `index.html` | 唯一页面。顶栏 + 公告条 + 一个 `<main id="view">`，视图整块替换 |
| `css/site.css` | 全部样式。两套皮肤：浅色是**网页粗野主义**（纯白底、纯黑字、蓝下划线链接、直角、零过渡零阴影零渐变），深色是**夜航玻璃拟态**（深墨夜景 + 柔光光斑、无色玻璃面板、香槟金强调色）。颜色、圆角、阴影、模糊、过渡一起走令牌，只有深色才做的取舍写在文件末尾一个 `[data-theme="dark"]` 块里 |
| `js/ui.js` | 渲染小工具，挂 `window.NM`。`esc()` / `formatDateTime()` 和几个枚举翻译都在这里，所有页面共用 |
| `js/api.js` | 请求入口。定义 `window.api`，在这里把 problem+json 解析成 Error |
| `js/auth.js` | token 的存取、当前用户、登录注册页、忘密码页、顶栏那一格（昵称链接；退出按钮在个人主页里） |
| `js/products.js` | 商品的列表、详情、发布、编辑、个人主页（我的商品 / 我买到的），以及用标题生成封面 |
| `js/messages.js` | 私信：会话列表、会话详情、发消息、交易面板、顶栏未读徽标 |
| `js/notifications.js` | 通知：列表、点开标已读、顶栏未读徽标 |
| `js/announcements.js` | 公告：顶部条、公告页、管理员的发布与删除 |
| `js/dictionaries.js` | 分类和宿舍区两本字典的管理页（增删改），带一道「只有管理员能进」的门 |
| `js/users.js` | 用户管理页（管理员）：按用户名/昵称/学号搜人，给忘了密码的人发一次性重置码 |
| `js/app.js` | 哈希路由、事件委托、主题、启动时的几处拉取（未读徽标、公告条、页脚的在线人数） |
| `vendor/jquery-3.7.1.min.js` | jQuery，原样入库 |

加载顺序有意义：`app.js` 最后，它启动时就要用到 `auth` / `messages` / `notifications` /
`announcements` / `dictionaries` / `users`——建路由表的时候就要引用它们。路由和处理函数都在
各模块自己的文件里，`app.js` 只负责把它们接起来。

## 运行

```bash
dotnet run --project src/NCUT_Market.Api --launch-profile http
```

打开 http://localhost:5087/ 。静态目录由 `Configuration/StaticWebRoot.cs` 解析，启动日志里有：

```
Serving frontend static files from <仓库根>\web
```

## 开发数据

空库看不出任何东西——分页、`srcset`、未读徽标都要有数据才立得起来。

```powershell
powershell -File db/seed-demo.ps1            # 约 20 用户 / 60 商品 / 25 会话
powershell -File db/seed-demo.ps1 -Reset     # 先清掉上一次的，再重来
```

脚本走真实 HTTP 接口，不是直接写表：密码要真哈希，图片要真过一遍 ImageSharp（否则缩略图
文件不存在，列表页全是一片灰底占位），上架还有状态机。占位图用 `System.Drawing` 现场画，
不需要任何新依赖。

跑完会打印账号，也会写一份 `db/demo-accounts.txt`（已 gitignore）。密码统一是 `Demo12345!`，
管理员那个账号的 `role` 是脚本用 SQL 提上去的——仓库里没有提权接口，这是唯一的手段。

**不加 `-Reset` 重跑是累加的**，用户名带随机后缀所以不会冲突，但数据会翻倍。

**这个文件不要编辑**，改一个字节哈希就对不上。`.gitattributes` 里的 `web/vendor/** -text`

文件长度和哈希都变。

## 两条不能省的写法

这两条不是"防患于未然"，是"这样写才对"：

**1. 服务端字符串插进 HTML 前必须过 `esc()`。** 视图整体用 `.html()` 重建，
所以每个拼进 HTML 的位置都要转义——标题、描述、昵称、消息正文、公告正文、通知正文、错误详情。
这些视图分散在 `products.js` / `messages.js` / `notifications.js` / `announcements.js` /
`dictionaries.js` / `users.js` 里，改哪一片都要留意。

配套的一条：正文里的换行交给 CSS 的 `white-space: pre-wrap`，**不要把 `\n` 替成 `<br>`**
再拼进去——替了就等于把用户输入又拼了一次 HTML。`ui.js` 里那句可以直接照抄。

**2. 时间字符串不要 `new Date()`。** 接口发的是北京时间的墙上时钟读数，没有时区后缀
（`"2026-09-29T13:43:09.037"`）。按 ES 规范，日期**时间**形式没偏移量时按**浏览器本地时间**
解析，所以 `new Date(v).toLocaleString()` 在任何非 UTC+8 的机器上都显示错——**唯独在开发机
（东八区）上是对的**，所以测不出来。直接按文本重排：

```js
value.replace("T", " ").slice(0, 16)
```

## 已知取舍

| 项 | 说明 |
|---|---|
| 「管理员专属」只是界面上的 | 导航三条链接和首页那几张入口卡按角色隐藏。直接敲 `#/categories` 或 `#/users` 会看到「没有权限」，直接敲 `#/products/new` 会看到表单、提交时才回 401。但 `/api/categories` 和 `/api/dormitory-areas` 的 GET **仍然是匿名的**——商品搜索栏的两个下拉和发布表单全靠它，锁掉整个商品页就废了。而且商品卡片本来就带着分类名和宿舍区名。**这不是访问控制，别当它是**；真正的判定在服务端。`/api/users` 是例外：它整个控制器都要求登录，且服务端逐次查库确认是不是管理员 |
| 重置码只显示这一次 | 管理员页生成完之后，码只在那一次响应里出现；刷新、翻页、重新搜索都会让它消失，库里存的是 SHA-256 摘要，服务端自己也拿不回明文。弄丢了就重新生成一个——重发即撤销，旧码当场失效，所以没有单独的「撤销」按钮 |
| 账号状态是单独一张枚举表 | `ui.js` 里有 `USER_STATUSES` + `userStatusText()`，**不能**复用商品那套 `statusText()`：`UserStatus` 的 2 是「已停用」，`ProductStatus` 的 2 是「在售」，直接混用会把停用显示成在售。两边都是 tinyint、都从 1 开始，编译器和类型都拦不住，所以分开放，并在 `out/check-frontend.js` 里钉了一条断言 |
| 用户搜索只有关键字 | 一个框同时匹配用户名、昵称和学号（包含匹配），没有角色/状态筛选，也没有排序选项。校园站几百个用户，够用 |
| 学号唯一，老账号没有 | 注册时必填，正则只钉住确认得了的两条：13 位数字、以 `20` 开头（挡住年份写成 `1024` 这类）。`2024322030157` 中间那五位含义不明，就不解释它。唯一索引 `uk_users_student_id` 是真保证，注册接口里那次查询只是把常见情况变成一句读得懂的 409。这一列可空且老账号留 NULL——非空列要有个默认值，所有老行拿到同一个占位串，唯一索引当场建不起来。它们在这个列表里显示 `—` |
| 密码找回是企业微信人工核验 | 没有邮箱也没有手机号，所以没有自助找回。忘了密码的人在企业微信上找 **计专研24田搏文** 报学号，管理员在用户管理页按学号搜到人、生成一次性重置码，用户自己去 `#/forgot` 换新密码。新密码是用户自己设的，管理员看不到——这正是选重置码而不是「发个临时密码」的理由。代价是这条链路要有人盯着，管理员不在就没人能重置 |
| 普通用户照样能用分类/宿舍区筛选 | 上面那条的推论。「不可见」指的是那两本字典的管理页，不是商品搜索 |
| 导航可能闪一下 | 被降权的管理员，本地缓存里的 `role` 是旧的，会在 `/me` 回来之前看到一眼管理入口。页面本身不会错——路由守卫等的是 `/me`。和公告页现在这个折中一模一样 |
| 分类树不处理孤儿 | 父分类被停用时，子分类的 `parentId` 不在结果集里，那一支**不会渲染**。现在的数据不会出现这种情况，真出现了再处理 |
| 分类一次拉 100 条 | 接口分页、树不分页，所以按 `MaxPageSize` 一次拉足，超过 100 个分类就只能显示前 100 个 |
| 会话只显示最新一页消息 | 接口给的是最新 20 条，页面会写明「共 N 条」。往上翻旧消息这一轮不做 |
| 交易面板不做前端预判 | 「下架」「标记已售出」在有待接受提议时照常显示，点了由服务端回一句中文 409。要做得更好就得往公开的商品投影里塞「有人在谈」这类信息，这一轮不值。可操作性仍然由服务端给的事实推出来（`ConversationTradeResponse`），只是不替服务端否决 |
| 拒绝和撤回是同一个接口 | `POST /transaction/cancel`：非发起方点叫拒绝，发起方点叫撤回，服务端只做一件事——清掉这条提议、给对方发一条通知，标题按点击者是谁分两句。少一个路由、少一个状态、少一个错误码，代价是路由名对两边都得中性 |
| 被拒绝后可以立刻重新发起 | 没有冷却期。拒绝清掉的只是这条提议，商品从没离开过在售，所以发起的前置条件当场重新满足。反复骚扰这一轮不挡 |
| 只有「撤回」要二次确认 | 拒绝不问。撤回一键生效、不可逆、还会推一条通知给对方，是全站唯一这样的按钮；拒绝的后果轻——对方马上就能重新发起。前端因此给这两个按钮各一个 `data-action`，都指向同一个 `/cancel`，好让确认只挂在撤回上 |
| 交易中的商品留在公开列表里 | 这是有意的：「别人正聊着，商品突然消失」正是要避免的。代价是列表里会出现暂时买不了的东西，靠「交易中」徽标区分 |
| 通知不轮询、没有「全部已读」 | 和私信徽标同一套：只在页面加载、登录状态变化、交易动作之后刷新，一条条点开 |
| 未读数不轮询 | 顶栏那两个数字只在页面加载、登录状态变化、读完一个会话之后刷新。两个人同时开着页面，对方发来的消息不会自动跳出来 |
| 私信输入框回车发送，但输入法选词时回车不算 | `app.js` 里挂了一条 `keydown`：回车走 `messages.send()`（和点「发送」同一个函数），`Shift+回车`留给换行——气泡是 `pre-wrap`，换行是真有用的。`event.isComposing` 那一问必须留着：中文输入法也用回车确认候选词，不挡的话一句话打到一半，选个字就把半截发出去了 |
| 会话列表那个数字是**条数**，顶栏徽标是**会话数** | 两个口径，故意不一样，而且并排出现在同一屏上：徽标回答「几个人在等我」，行里的数字回答「几句话没看」。`ConversationSummaryResponse.UnreadCount` 是前者要反的那一面——它数的是「对方写了几条我没有读」，和 `UnreadConversations` 用的是同一个已读戳比较，只是 `Count` 而不是 `Any` |
| 删私信是**单方面隐藏**，不是真删 | 会话是两个人共用的一行，所以删的只是我列表里的那一行：`buyer_deleted_at` / `seller_deleted_at` 一格一侧，对方那边原封不动。**而且任何一方再写一句话，两边的标记都清掉，会话对双方一起回来**——不能单方面把别人静音，删错了也不会永久丢消息。唯一的例外是**交易进行中**的会话：确认收货/确认收款的按钮只长在会话页里，藏掉它等于让人没地方点，所以服务端回 409；交易完成之后随便删 |
| 通知分组在前端做 | 服务端列表仍是扁平的、按时间倒序、按条分页，一个字没动；`notifications.js` 的 `groupItems()` 拿 `relatedProductId` 现分。代价是**分页边界会把一个商品的通知切开**，出现相邻两组同名商品——一页 20 条、一笔交易最多 6 条，实际很少见。换来的是不用写本仓库第一处 SQL `GroupBy`，也不用为分组另算一遍 `totalCount`。组标题来自 `NotificationResponse.ProductTitle`（列表时从导航属性现读，不是冻结进正文的） |
| 商品被硬删之后，它的那组退化成单条删 | 外键是 `SET NULL`，所以 `relatedProductId` 归 null、组标题变成「已删除的商品」。这时按商品删没有 id 可用，按钮退化成 `DELETE /api/notifications/{id}` 删那一条——而那一组本来就只剩一条 |
| 点开看的是 1280 那张，不是原图 | 详情页格子是 200px 方形裁切，点开后页内浮层铺满视口、按原比例显示整张（`ImageStorage` 写 1280 那张用的是 `ResizeMode.Max`，比例没动）。上传的原始字节没有留——存储里只有 1280/640/320 三种派生——所以「完整」指的是比例完整，不是分辨率最大。浮层放在详情页标记里而不是挂在 `body` 上：`route()` 换页整块重建 `#view`，等于换页自动关掉它 |
| 页脚的在线人数同样不轮询 | 只在页面加载时拉一次 `/api/online/count`（匿名可读）。所以它是一个快照：坐在页面上不动二十分钟，数字不会自己变小 |
| 公告条按 id 记「已关闭」 | 关掉之后存在 localStorage 里，刷新不再弹；但发一条新的照样会出现 |
| 未登录：发布藏起来，别的进去提示登录 | 两种处理，不是一种。**发布**整个不显示（顶栏那条 + 首页、商品列表卡片头那两个按钮，`app.js` 的 `paintNavVisibility()` 按 `data-signin-only` 统一切）。**个人主页 / 私信 / 通知**照常摆在顶栏上，未登录点进去看到的是 `NM.signInCard()` 那张「请先登录」——挡在页面入口而不是等接口回 401，因为 401 会先渲染出一张空列表、再被人弹到登录页，中间那一跳很难看。**两种都不是访问控制**：直接敲地址照样进得去，真正的判定在服务端 |
| 顶栏叫「个人主页」，第一张卡才叫「我的商品」 | `#/mine` 现在是三张卡的个人主页（我的商品 / 我买到的 / 账号），不是一个列表。之前拿第一张卡的名字当整页的名字，同一条路径上「我的商品」会同时是入口标签、页名和卡片标题三样东西，右上角昵称那格的兜底文本又正好也是它。现在页名是 h1「个人主页」，各张卡退回 h2；顶栏那条和昵称的兜底文本都跟着页面走。**入口仍然有两条**（顶栏 + 昵称），都指这里——那是有意的，未登录时顶栏那条不能消失，点进去要看到「请先登录」 |
| 退出按钮在个人主页里，不在顶栏 | 它和顶栏那排导航链接长得一样、挨得又近，点错的代价是当场登出。挪到个人页之后要多点一次，但误触不会了。也没加二次确认——挪位置已经解决了问题，再加一个弹窗是把又一次点击当成保险 |
| 前端测试只覆盖纯函数 | `out/check-frontend.js` 测 `esc` / `formatDateTime` / `treeHtml` / `userStatusText` / `coverLines` 这些不碰 DOM 的函数，外加一道「use strict 下有没有漏声明变量」。视图、请求和 canvas 画图得靠手点 |
| 在线人数只算登录用户 | 系统发的是 JWT，服务端没有会话，分不出两个匿名请求是不是同一个人——同一个游客刷新十遍，看到的是十个互不相干的请求。所以这个数的意思是「最近 5 分钟有过请求的活跃账号」，不是「此刻开着页面的人数」。页脚那句「近 5 分钟有活动的登录用户」就是为了不让人误读。`users.last_seen_at` 由 `Program.cs` 里一段中间件盖，只在带 token 的请求上写，匿名请求一次写都不产生 |
| 在线人数每请求一条 UPDATE | `OnlineService.TouchAsync` 每次都盲目写一次，没有节流。节流要先读一次再决定写不写，反而更贵；校园站这个量级不值得优化。写走的是 `ExecuteUpdateAsync`，绕开 `AppDbContext` 的审计规则，所以心跳不会把 `users.updated_at` 也改掉 |
| `last_seen_at` 不建索引、停用账号不算在线 | 前者：`users` 只有几百行，这一列每个请求都要重写，建索引是倒贴写放大。后者：停用账号的 token 照样验得过、照样会被盖时间戳，但一个什么都做不了的账号挂在「在线」上只会把数字说大 |
| 正文 14px 宋体，不是 12px | **浅色的事**。当年确实是 12px，但 SimSun 在高分屏上低于 13px 就糊了——那是坏了不是复古。想还原的话改 `:root` 的 `body { font-size }`。深色用的是系统无衬线（`--font-body`）：玻璃面板上没有做旧这回事，暗底上的细笔画也更吃亏 |
| 按钮面是 `#dfdfdf`，不是纯白 | **浅色的事**。「背景只能是纯白」和「按钮必须有 Windows 95 斜面」是打架的——白面配白色上/左边框，斜面根本看不见。所以按钮用系统银灰面，其余一切纯白。输入框同理，凹进去。深色把这套「系统铬色」换成玻璃：四个斜面色给成同一个值，那条四色边框就自然塌成一条 1px 的均匀白线 |
| 弱化色没做成纯黑 | **浅色的事**。规范要求正文弱化色也用纯黑、靠结构分层次。但 12px 的成色/时间/页码全黑会糊成一片，用了 `#444444`。深色是 `white/.60`——它在 `#0b1322` 上是 ~7:1，过 AA |
| 只有正文链接有 hover 变色 | **浅色的事**。按钮没有 hover 态——当年的按钮就没有，状态只发生在按下那一瞬间。卡片和列表行的 hover 只改边框色或字色，不改底色。深色反过来：卡片和按钮 hover 上浮，列表行浮起一层薄白 |
| 复古感靠结构不靠动效 | **浅色的事**。没有 `<marquee>`，没有闪烁，也没有扫描线。零过渡、零动画 |
| 深色是玻璃拟态，不再是黑白反相 | 早先那版黑底绿字终端、以及后来的黑白反相，都换掉了。深色现在是一套**结构上也不同**的皮肤：夜景渐变底 + 柔光光斑、无色玻璃面板（`backdrop-filter`）、香槟金唯一强调色、圆角和 spring 过渡。所以文件里的纪律改成两层——能用**一个值**表达的继续走令牌（浅色令牌的值就是原先的字面量，浅色因此由构造保证不变），只有深色才做的取舍集中在文件末尾那个 `[data-theme="dark"]` 块里。链接在夜景底上是 `white/.88`，下划线 `white/.32`；弱化色 `white/.60` 约 7:1，已售出徽标是 12px 粗体、不算大号文字，所以从规格里的 `.40`（~3.4:1，不达标）提到 `.52`（~5.2:1） |
| 下拉框弹出的列表只管得了颜色，管不了圆角 | 筛选栏那几个 `<select>` 是 `appearance: none` 的，控件本体走令牌（圆角、玻璃面、白字），但它们**弹出的那层列表**是浏览器自己画的：底色跟 `color-scheme`、字色从 `select` 继承。两条都不是令牌，所以深色下得单独处理——`:root[data-theme="dark"]` 里给 `color-scheme: dark`（顺带定了滚动条和数字框的箭头），再给 `option` 一个不透明的夜色面，否则 6% 的白玻璃落在列表底上就是白底白字。**列表的方角改不掉**，除非开 `appearance: base-select` 把它换成 `::picker(select)`；试过，那个值会给下拉框加一个箭头图标，筛选栏那几格本来就将将放得下，一加就换行、搜索按钮也被挤出去，所以没开。真要做得圆角，得先给 `.filter-bar` 重新排一遍 |
| 深色下的面板模糊只给三处 | `.site-header`、`.announcement-bar`、`.card`——内容真的从底下经过的地方。套在已经模糊过的 `.card` 里面的面板再叠一层在视觉上是空操作，只是白付合成层。另外 `backdrop-filter` 非 `none` 会给内部的 fixed/absolute 后代当含块，所以详情页的看图浮层是 `.card` 的**兄弟**而不是子节点（见 `products.js` 的 `detailHtml`）——放里面的话它只在深色下塌成卡片那么大 |
| `/favicon.ico` 404 | 仓库里的图片只有页脚那两个仓库图标（`web/img/*.webp`），没有 favicon。商品封面是用户传上来的数据，不是仓库里的文件 |
| 生成的封面把字烤进了图里 | 发布之后改标题，封面还是旧标题，只能在编辑页删掉重画。这是「生成一张真图片」的必然代价。另外它是位图，不跟深色主题走——同一张图在两种主题下长得一样 |
| 生成封面在浏览器里画，不在服务端 | 服务端画中文要引 `SixLabors.Fonts`，还得往仓库塞一份可再分发的中文字体（十几 MB，授权另算）。浏览器里字体是现成的，`db/seed-demo.ps1` 能画是因为它跑在 Windows 上调系统字体，那是脚本不是服务。代价是发图之前浏览器必须支持 canvas `toBlob`——都是它 |
| 生成封面排在最后，只覆盖发布页 | 手选的照片先传，所以有真照片时它仍然排第一张当封面；一张照片都没选时生成的那张才轮到 `SortOrder = 0`。编辑页（加图删图现在都在那边）没放同一个按钮，这一轮不做 |
| 加图删图在编辑页，不在详情页 | 两处原本并排摆着——改一段文字要点「编辑」，换一张照片要在详情页点「上传图片」，同一个商品两套入口。现在详情页对谁都是纯展示，增删都收进编辑页。图片那一段在 `<form>` **外面**，因为加图和删图各走各的接口、点了就生效，不归「保存」管；页面上写明这一点，免得改完图片点「取消」以为白改了。改完只重画 `#edit-images` 那一块，不整页重来——整页重来会把表单里刚打的标题冲掉 |
| 删除分两种，看商品是不是走平台交易卖的 | `products.deleted_at` 只在**成交过平台交易**（`transaction_buyer_id` 非空）的商品上写。那种商品的行不能真删：交易记录不是副本，它就是这一行上的 `transaction_*` 几列，删了 `ConversationService` 那个投影会全变 null，双方会话里的交易面板连同确认收货/确认收款的整个过程一起消失。所以那种「删除」只是标一下，商品从列表、搜索、「我的商品」里消失，详情页对所有人（卖家也算）404，私信里那块面板原样留着。反过来，卖家自己下架、或者自己点「标记已售出」的商品没有任何线程记着它，照旧连行带图真删。前端靠服务端给的 `keepsTradeRecord` 决定确认框说哪一句话——一种删完还找得回来，另一种找不回来 |
| 软删的商品，会话里的商品链接也没了 | `ConversationDetailResponse.productId` 在两种情况下都是 null：真删掉的（外键被 SET NULL），和卖家删掉的（行还在，但那一页已经 404）。前端因此走同一个「商品已删除」分支——标题用的是建会话时冻结下来的那份，缩略图同理。不给链接是因为跳过去只会看到 404。**这和交易面板是两回事**：链接没了不代表记录没了 |
| 「我买到的」只算走完的平台交易 | 判据是 `transaction_buyer_id == 我 && status == 已售出`，两半都不能少。只看状态会把扫尾回滚过的交易也算进来（那种商品已经退回在售，但走过一遍已售出的状态）；只看买家列会把还在谈的算成买到了。**卖家在详情页点「标记已售出」成交的那笔永远进不来**——那条路刻意不写任何 `transaction_*` 列（没有对手方可记），所以它的买家在库里根本不存在。一个人大部分成交如果都是手标的，这个列表就是空的。要修的话得让卖家标售出时从自己的会话里挑一个买家，那等于把两条路合并，这一轮不做 |
| 「我买到的」的卡片都点不动 | 卖家把自己列表里清掉的那个成交（软删）仍然显示在买家的记录里——他花过钱，不该因为卖家整理页面就消失——但那个详情页对谁都是 404。与其一部分能点、一部分点了报错，整列都做成不可点的凭据（`cardHtml` 的第二个参数传 `null` 出 `<div>` 而不是 `<a>`）。代价是一个**还活着**的成交也点不进去了；买家想看那个商品，从私信那一串的标题链过去。CSS 那边跟着用 `.product-card[href]:hover` 把 hover 高亮关掉——点不动的东西亮边框等于骗人 |
| 「我买到的」卡上是发布日，不是成交日 | 列表按成交时间倒序（`sold_at`），但卡片那行日期读的是 `createdAt`，因为它在共用的 `ProductSummaryResponse` 上、而那个 DTO 没有成交时间。给共用的 DTO 加字段会让这个时间出现在所有商品列表里。看着别扭再说 |
| `#/mine` 的 hash 里有两个页码 | 「我的商品」是 `?page=`，「我买到的」是 `?boughtPage=`。翻一个要把另一个原样带着（`mineHref`），否则翻「我买到的」会把「我的商品」踢回第一页。两个列表各发各的请求，一张卡挂掉不影响另一张 |
| 分类/宿舍区字典被软删的商品挡住 | `CategoryService` / `DormitoryAreaService` 删字典项前那句 `AnyAsync(Products)` 没有排除 `deleted_at`，所以一个已经被卖家删掉的商品仍然会挡住它所属的分类。要求是先删干净字典项再删商品，实际不会撞上；真撞上了再排 |
| 生成封面不改「上架必须有图」 | `ProductService.PublishAsync` 那道检查保留：至少一张图这条规则本身是对的，这一轮是给它配了条出路，不是把它拆掉。客户端也仍然不预检有没有图，撞到 400 才提示 |
| `/README.md` 可公开访问 | 内容无敏感信息 |
| 页脚的仓库链接写死在 `<footer>` 里 | Gitee 是 `origin`（`tian_puwen/ncut_-market`），GitHub 是 `github` 远程（`foolbirdtbw/NCUT_Market`），两边推同一份 master。换远程要连 `index.html` 一起改——许可证那条链接也指向 GitHub，同理。仓库里没有 `.env`——`.gitignore` 挡着，跟踪的只有 `.env.example` 那份 `Password=replace-me` 占位值，所以推公开仓库不漏数据库密码 |
| 页脚的仓库链接摆右边、用图标 | 左边那句话和「接口文档」链接挨得近，再加两个文字链接就连成一片，读不出哪块是哪块。两张图标其实不是一回事：Gitee 那张自带透明通道，本身就是个红色的圆；GitHub 那张是不透明的，白圆盘画在黑方底上，不裁的话浅色主题下就是个黑方块。所以 `border-radius: 50%` 是为 GitHub 那张加的，对 Gitee 是空操作 |
| 图标必须放在 `web/` 下面 | `NCUT_Market.Api.csproj` 只把 `web/` 下的文件当静态内容收进发布产物。放 `db/`（或者仓库里任何别的地方）开发时能读到、发布出去就 404。所以是从 `db/` 挪到 `web/img/` 的。源图是 1280×1280 和 512×512，实际只画 20px，没有压缩——校园站不在乎这 64 KB |
| 前后端同源部署 | 前端绑在 API 进程上，所以没有 CORS 配置 |

`out/` 整体是构建产物，只有 `check-frontend.js` 被 `.gitignore` 反向包含进来。**用 PowerShell 跑**：

```powershell
node out/check-frontend.js
```

Git Bash 会把 `TZ` 吞掉，那样连跑几次其实都是同一个时区，测了等于没测。
